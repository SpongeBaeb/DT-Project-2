# Sea Marksman 웹 (web_sm7): 소개 화면과 서비스 화면 개편판

web_sm6의 기능과 데이터 연결은 그대로 두고 화면을 두 갈래로 나눴습니다. web_sm6은 그대로 둡니다.
- 소개 화면: 홈, 서비스 소개, 선종별 현황, 2026 리스트, 지표와 근거. Stark Shipping 사이트의 구성과 움직임을 참고했습니다(큰 글씨, 스크롤 연출, 전체 화면 메뉴).
- 서비스 화면: 찾기, 진단, 리스트 표, 선대, 비용, 내 선박, 비교, 관심. 2번 예시 화면처럼 왼쪽 메뉴와 짙은 패널로 구성했고, 처음에는 어두운 화면으로 열립니다.

## 실행
- 프로젝트 폴더의 `run_sea_marksman_v7.bat`을 실행하면 팀 모델 API(8000)와 웹 http://localhost:5192 가 함께 켜집니다.
- 검사: `npm test` (16개), `npm run build`, 서버: `python -m pytest tests` (`tests/unit/test_ais.py` 포함)
- 개발 서버가 다른 API 주소를 보게 하려면 `API_URL=http://127.0.0.1:8001` 환경 변수를 줍니다.

## 화면과 주소
| 주소 | 화면 |
|---|---|
| `#/` | 홈. 배가 돌며 등장하는 첫 화면 → 서비스 한 문단 → 흐르는 띠 → TIGANI 사례 → 등급을 흐리는 네 가지 → 12,610척 중 234척 → 13개 선종(사진이 화면 쪽으로 다가옴) → 2026 리스트 → 진단·비용 소개 → 검증 66% |
| `#/about` | 서비스 소개: 떼어 내는 것 4가지, 진단 화면에서 보는 것 5가지, 규제 연표, 하지 않는 것 |
| `#/types`, `#/types/<선종>` | 선종 줄 목록(마우스를 올리면 사진) / 선종 상세(등급 분포, 동급보다 더 쓰는 이유, 2026 영업 타깃 상위) |
| `#/list` | 2026 리스트 상위 20척. 전체 표는 `#/table` |
| `#/method` | 지표와 근거 |
| `#/search` `#/ship/<IMO>` `#/table` `#/fleet` `#/cost` `#/my` `#/compare` `#/watch` | 서비스 화면 |

## 화면 구성 (스크롤 줄이기)
화면 높이는 1440×900 기준입니다.

| 화면 | 이전 | 이후 | 방법 |
|---|---|---|---|
| 선박 진단 | 8.0 | 1.4~2.1 (탭별) | 머리 압축, 탭 6개(착시 점검·효율·원인·전망·비용·점검·유사 선박·공용 서버 값), 카드를 2~3열로 배치 |
| 비용 계산 | 5.5 | 1.0~2.3 (탭별) | 탭 5개(비용 전망·공용 서버 경제 계산·가격·시나리오 계산·전년 대비 변화·시장 지표) |
| 지표와 근거 | 4.4 | 2.4 | 탭 4개, 표를 한 화면에 |
| 선박 찾기 | 7.9 | 3.2 | 필터 그룹 접기, 결과 행 압축, 20척씩 |
| 2026 리스트 | 5.0 / 표 4.8 | 3.2 / 2.8 | 20척·25척씩 |
| 홈 | 14.4 | 11.4 | 스크롤 고정 구간 단축, 간격 압축, 도구 소개를 2열로 |
| 서비스 소개 | 6.7 | 4.8 | 번호 목록 2열 |

진단 탭은 주소의 `?tab=eff|fc|cost|chk|srv`로 바로 열 수 있고, 인쇄할 때는 모든 탭이 함께 출력됩니다.

## 공용 서버 값 (진단 > 공용 서버 값 탭, 비용 > 공용 서버 경제 계산 탭)
- `/ships/{imo}`: 서버가 MRV 원자료로 계산한 CII 등급·비율·달성/요구 CII를 팀 모델 값과 대조(일치/다름 표시)
- `/ships/{imo}` 규제 평가: 필요 개선율, 기준 확률 p*, 미달 확률. 이 서버 버전은 예측 모델이 없어 "미평가"로 내려오며 화면에도 그대로 표시
- `/cluster/*`: 군집 소속 확률(3유형), 이상치, 저속 운항, 설계 효율; 군집 품질(실루엣·안정성)과 연결 현황은 지표와 근거 화면
- `/economics/*`: 선박별 사전계산 비용과 원인 분해(해상 효율·정박·규제·연료 가격·배출권 가격), 1해리당 비용, 동급 대비 격차, 점검 플래그. 서버의 가격 시나리오를 입력 가격으로 적용 가능
- 반영하지 않은 것: `/meta`, `/frontend/*`(팀 모델 메타와 중복), `/market/snapshot`·운임 지수(값 없음), `/ships` 목록·`/simulate`(MOCK)

## 선박 현재 위치 (AIS)
진단 화면의 선박 사진 옆에 지도가 표시됩니다. 위치는 aisstream.io의 AIS 수신값입니다.
- 키: 프로젝트 루트 `.env`의 `AISSTREAM_API_KEY`. 브라우저에는 노출되지 않고, 서버(`api/ais.py`)만 aisstream에 접속합니다.
- 흐름: 서버가 실행 중 aisstream에 한 번 접속해 우리 선박(22,667척)만 모읍니다. 화면은 `/api/ais/{imo}`를 받아 갱신합니다 (수신 전 12초, 수신 후 60초).
- 선박 식별: aisstream은 MMSI 기준이라, AIS 정적 메시지(IMO·MMSI 함께 옴, 선박당 약 6분에 한 번)로 IMO→MMSI 표를 만듭니다. 표와 마지막 위치는 `data/ais/state.json`에 저장되어 다음 실행 때 바로 쓰입니다.
- 서버를 켠 직후에는 위치가 비어 있고, 몇 분 지나면 채워집니다. 서버를 오래 켜 둘수록 표시되는 선박이 늘어납니다 (6분 만에 309척 매칭, 실측).
- 한계: 육상 수신국 중심이라 먼바다 선박은 신호가 없을 수 있고, 6시간 넘게 수신이 없으면 "오래된 값"으로 표시합니다. 과거 항적은 제공되지 않습니다. 수신이 매 1~2분 끊기기도 하며 자동으로 재접속합니다.
- 끄기: 환경 변수 `SEA_AIS=0`. 키가 없으면 수집하지 않고 화면에 안내만 나옵니다.
- 확인 필요: aisstream 이용 약관(상업적 이용 여부)은 문서에서 확인하지 못했습니다. 외부 공개 전에 확인하세요.

## 새로 쓴 것
- 로고 `src/components/Logo.tsx`: 조준경 원, 수평선을 겸하는 조준선, 선체, 둘이 만나는 곳의 주황 표적 점. 파비콘은 `public/favicon.svg`
- 움직임 `src/motion.ts`: Lenis(부드러운 스크롤, 소개 화면에서만)와 GSAP ScrollTrigger. 움직임 줄이기 설정이나 좁은 화면에서는 정지 화면으로 바뀝니다.
- 글꼴(모두 프로젝트 안에 포함): 제목은 Archivo 넓은 폭(npm) + G마켓 산스(`public/fonts`), 본문은 Pretendard(npm)
- 이미지
  - `public/hero-ship.webp`: 1번 이미지(상부도, 투명 배경)
  - `public/types/*.webp`: 선종별 대표 이미지 13종, 1200px·560px. manifest 기준 생성 이미지이며 특정 선박이 아님(화면에 표시)
  - `public/shots/*.webp`: 진단·비용 화면 캡처
- 문구: 용어보다 배와 돈에 생기는 일을 먼저 쓰고, 한 문장에 한 가지만 담았습니다. 판정 설명(`verdict.ts`)과 지표와 근거 비교표도 같은 기준으로 고쳤습니다.
